# RhythmMaster
一款基于 Qt Widgets 开发的桌面端音乐节奏游戏，玩家需在正确时机按下对应按键打击下落音符以获取高分，项目保留完整的核心功能、数据结构和算法逻辑，支持谱面加载、音频同步、分数统计和排行榜持久化。

## 项目亮点
1.  **完整核心功能**：包含音符下落、实时判定、连击系统、分数计算、音频同步等节奏游戏核心模块。
2.  **模块化设计**：数据层、逻辑层、界面层分离，低耦合、高可扩展性，便于后续新增功能（如新增音符类型、皮肤系统）。
3.  **严谨的数据结构**：封装完善的核心数据类，支持游戏状态记录、统计分析和数据持久化。
4.  **标准 Qt 实现**：基于 Qt Widgets 构建图形界面，跨平台兼容（Windows/macOS/Linux）。

## 环境要求
### 开发/运行环境
- **Qt 版本**：Qt 5.15 及以上（推荐 Qt 6.2 LTS，兼容更好）
- **编译器**：
  - Windows：MinGW 8.1 及以上 / MSVC 2019 及以上
  - macOS：Clang 12 及以上
  - Linux：GCC 9 及以上
- **C++ 标准**：C++17 及以上
- **额外依赖**：Qt Multimedia 模块（用于音频播放与同步）

### 资源准备
提前在项目根目录创建 `Resources` 文件夹并放入对应资源（目录结构见下文）：
- 音频文件（支持 .mp3、.wav 格式）
- 谱面文件（自定义格式，可参考 JSON/XML 规范）
- 图片资源（歌曲封面、音符皮肤、界面背景等）

## 快速开始
### 1. 克隆/获取项目
将项目完整下载到本地，确保目录结构完整，无缺失文件。

### 2. 打开项目
1.  启动 Qt Creator，点击「打开项目」，选择项目根目录下的 `RhythmMaster.pro` 文件。
2.  Qt Creator 会自动解析项目配置，等待依赖加载完成（无需手动配置，`pro` 文件已预设完整依赖）。

### 3. 编译项目
1.  选择对应的编译套件（如 MinGW 64-bit）。
2.  点击「构建项目」（快捷键 Ctrl+B），等待编译完成（无报错即编译成功）。

### 4. 运行游戏
1.  点击「运行项目」（快捷键 Ctrl+R）。
2.  启动后进入主窗口，选择歌曲即可开始游玩。

## 核心功能说明
### 1. 核心游戏流程
1.  玩家在主窗口选择歌曲和难度。
2.  游戏加载对应谱面和音频文件，初始化玩家状态和游戏配置。
3.  音频播放，音符随节奏下落，玩家按下对应按键进行打击。
4.  实时判定按键结果（Perfect/Great/Good/Miss），更新分数和连击。
5.  游戏结束后，汇总游玩统计数据，展示结果界面并更新排行榜。

### 2. 关键模块功能
| 模块 | 核心职责 | 关键特性 |
|------|----------|----------|
| `NoteManager` | 音符生命周期管理 | 音符激活/过期判断、位置实时更新、活跃音符筛选 |
| `AudioSync` | 音频与音符同步 | 精确获取音频播放时间、偏移补偿、播放/暂停/停止控制 |
| `ScoreCalculator` | 分数与判定计算 | 基于时间差的判定等级映射、连击倍数加成、准确率计算 |
| `BeatmapLoader` | 谱面解析与加载 | 数据验证、错误处理、构建完整 `Beatmap` 实例 |

### 3. 判定与分数规则
- 判定等级（按时间差从小到大）：Perfect > Great > Good > Miss
- 基础得分：Perfect（300分）、Great（100分）、Good（50分）、Miss（0分）
- 连击加成：连击数越高，额外得分倍数越高，中断连击后加成重置
- 准确率：`(Perfect*300 + Great*100 + Good*50) / (总音符数*300) * 100%`

## 开发指南
### 1. 开发优先级
遵循「**数据层 → 逻辑层 → 界面层**」的顺序开发，确保每一层功能完整且可独立测试：
1.  先实现 `Core/Common.h`（枚举/常量）。
2.  实现 `Core` 目录下所有数据类（确保 getter/setter 正确，功能方法逻辑闭环）。
3.  实现 `Logic` 目录下的核心逻辑类（优先 `NoteManager` 和 `ScoreCalculator`）。
4.  实现 `UI` 目录下的界面类（优先 `GameScene` 确保可视化效果）。
5.  整合所有模块，测试完整游戏流程，完善持久化功能。

### 2. 代码规范
- 类名：大驼峰（PascalCase），如 `NoteManager`、`GameScene`。
- 函数/变量名：小驼峰（camelCase），如 `calculateAccuracy`、`totalScore`。
- 常量：全大写+下划线（UPPER_CASE_UNDERSCORE），如 `DEFAULT_NOTE_SPEED`。
- 注释：使用 Doxygen 规范，所有类、公共方法必须添加注释（@brief、@param、@return）。

### 3. 测试规范
- 每个核心类完成后，编写独立测试代码验证功能（如验收标准中的 `assert` 测试）。
- 逻辑层方法优先进行单元测试，确保无业务逻辑错误。
- 整合测试时，重点验证音频与音符的同步性、判定的准确性和分数计算的正确性。
